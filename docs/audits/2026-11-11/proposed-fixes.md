## Separate product decisions / investigation

- **Unseen previous-lease audio:** current native protocol has no lease ID and the limitation is documented. Decide whether guaranteed exclusion justifies media association rotation/client reconnects. A small timing quarantine cannot guarantee arbitrary unseen UDP age; do not present it as complete prevention.
- **Interrupted settings/credential save:** decide crash-recovery guarantees. A generation/manifest or recoverable transaction can keep the pair coherent, but must preserve Windows/macOS encryption and Linux separate-private-file behavior. First specify recovery and migration, then add killed-subprocess tests. Do not silently fall back to plaintext.
- **BFCache:** reproduce pageshow.persisted on an actual supported browser first. If reachable, revalidate the session/resume polling on restore; expired session still goes to login. VM events alone are not browser eligibility proof.
- **Documentation polish:** README initially says no web UI while a later section describes Linux web mode; cache savings text predates independent telemetry polling. Clarify per-request local answers versus net physical radio traffic. These are low-risk clarity improvements, not proof of runtime failure.

## Release validation after selected fixes

1. Keep source changes small, with each relevant expected-invariant probe promoted into meaningful regression coverage. Independent reviewer should inspect the resulting diff without relying on this plan as proof.
2. Run full tests/lint/check, pack dry-run and all relevant loopback fault probes. Retain current-source CI on Windows/macOS/Linux with supported Node versions.
3. Build and smoke fresh native Windows x64, macOS Intel/ARM and Linux x64/ARM binaries. Specifically exercise the newer Linux packaged web assets/startup with no source checkout present, its service directory/TLS/profile persistence, and normal stop/reboot recovery in a test environment.
4. Repeat installed desktop smoke in an interactive macOS session with usable Keychain; validate Windows OS-vault behavior. Do not bypass encryption to manufacture a pass.
5. Any current Pi inspection remains read-only until a separate deployment request. Physical TX/CW/VOX/tuner/voice/RF tests need a new bounded authorization and suitable setup; none are implied by this audit. Preserve active users and configuration.
6. Select a new identifiable release version: v0.8.1 binaries predate the current features. Build provenance/checksums, instructions and download labels must match the chosen source. Publishing/deployment require the owner's subsequent instruction.

## Suggested first batch

AUD-01 + AUD-02 + helper-local generation fences, with independent review and fixture failure tests, is the recommended first batch. This addresses the cleanup path without bundling UI, metric or packaging changes. Transport recovery/backpressure should be a second reviewed batch; diagnostic and narrow UI/validator fixes can follow independently.
